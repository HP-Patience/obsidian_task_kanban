# 每日页 / 任务页 冗余与切换成本分析

> 日期：2026-09-26 ｜ 基线：`插件源码/lubi/src/ui/`（`view.ts`、`today.ts`、`tasks.ts`、`taskList.ts`）
> 依据：源码走查 + `docs/images/today-light.webp`、`docs/images/tasks-week.webp`

## 1. 结论

两页确实冗余较多。问题不在“有两个页面”，而在于它们**都在回答“今天”**：

- 每日页回答“今天实际做了什么”，但右栏又放了“今天要做什么”；
- 任务页回答“这周怎么排”，但左栏第一张卡又是“今天要做什么”，周日程里还有“今天”这一列。

于是同一件事（例：`线性代数 第 4 章`）在两页里出现 **4 次**：
时间轴记录块、每日页“今日待办”、任务页“今天”清单、周日程周六列。
而用户真正想对照的“计划 vs 实际”，反而必须来回切页才能看到。

## 2. 冗余清单

| # | 冗余点 | 位置 | 说明 |
|---|---|---|---|
| R1 | 同一份“今天”清单渲染两次 | `today.ts` `renderTodayTasks` / `tasks.ts` `renderLists` | 都调用 `renderDayTaskList`，内容、交互完全相同 |
| R2 | 两套竖向时间网格 | `today.ts`（0–24 点，`HOUR_PX = 56`）/ `tasks.ts` `renderWeek`（按设置起止，`HOUR_PX = 44`） | 同一天的计划在一个网格、实际在另一个网格，刻度还不一致 |
| R3 | 两套“空白处拖出”手势 | 每日页拖出 = 新**记录**；周日程拖出 = 新**任务** | 手势一样、结果不同，要靠“我现在在哪一页”来区分 |
| R4 | 三套日期导航 | 顶栏 `‹ 日期 › 今天`（只在每日页生效）、周日程 `‹ 本周 ›`、窄屏议程 `‹ 今天 ›` | `view.date` 与 `tasksState.selectedDate / weekAnchor / agendaDate` 是**各自独立**的状态 |
| R5 | 跳转按钮本身就是切页 | 每日页“今日待办”右上角“在任务页安排” | 用户想排一下就得离开当前页面 |

## 3. 视觉切换成本（为什么“切起来累”）

| # | 现象 | 源码 |
|---|---|---|
| V1 | 待办清单**左右换边**：每日页在右栏，任务页在左栏 | `lubi-today-side` / `lubi-tasks-left` |
| V2 | 顶栏左区**换内容**：每日页是日期导航，任务页变成“任务 · 本周 9/21 – 9/27”文字 | `view.ts` `render()` / `contextText()` |
| V3 | 日期**不跟随**：每日页翻到 9/24，切到任务页仍停在任务页自己上次的日期；反过来也一样 | `view.ts` `setTab()` 只在首次进入回顾页时同步日期 |
| V4 | 快捷键**失效**：`←/→`、`T` 在任务页不起作用 | `view.ts` `onKey()` 里的 `this.tab === "today"` 判断 |
| V5 | 时间刻度**不同**：56 px/h 对 44 px/h，起止时间也不同；同一时刻在两页的纵向位置不一样 | `today.ts` / `tasks.ts` 的 `HOUR_PX` 常量 |

## 4. 方案

### 方案 A：只做一致性，不改结构（约 0.5–1 天，风险低）

1. **统一日期状态**：`DashboardView` 只保留一个 `date`；任务页的 `selectedDate` 由它推导，`weekAnchor` 取它所在的周。顶栏日期导航在两页都生效，`←/→`、`T` 在两页都可用（任务页按天移动选中日，跨周时周日程自动翻页）。
2. **待办固定一侧**：两页的待办、未安排都放右栏（或都放左栏），切页时眼睛不用跳。
3. **统一时间刻度**：抽出 `HOUR_PX` 常量共用，周日程起止与每日页首屏范围对齐。
4. 顶栏左区在任务页也显示日期导航，周范围作为副标题。

→ 解决 V1–V5，但 R1–R3 的重复还在。

### 方案 B（推荐）：每日页 = 今天的计划 + 实际；任务页 = 纯规划（约 2–3 天）

1. **时间轴叠加“计划层”**：当天有开始时间的任务，在时间轴上画成虚线框的半透明块（和实线的记录块区分开）。
   - 点击计划块 → “开始 / 记一条”（复用 `openLogFor`）；记完后计划块变为 ✓ 并淡出；
   - 计划与实际一眼对照，不用再切页（这也正是柳比歇夫法的核心：计划与实际对账）。
2. **每日页右栏待办**只保留“没定时间的今日任务”；定了时间的已经画在时间轴上，不再重复列出。
3. **任务页去掉“今天”卡**：左栏改成“选中日”（由周日程点表头切换）+ 未安排 + 项目，专注排期。
4. 每日页右栏加一个“未安排 N”折叠区，可以直接拖到时间轴上排进今天，替代“在任务页安排”这个跳转按钮（解决 R5）。
5. 同时落实方案 A 的第 1、2、3 条。

→ 两页分工清晰：**每日 = 今天（做 + 记）**，**任务 = 以后（排）**；每条信息只在一个主位置出现。

### 方案 C：合并成一个“日程”页，日 / 周切换（约 4–6 天，改动大）

- Tab 从“每日 / 回顾 / 任务”变为“日程 / 回顾”；日程页内切换“日 | 周”；
- 日视图 = 方案 B 的时间轴（计划 + 实际）；周视图 = 7 列，每列同样叠加计划与实际；
- 右侧固定抽屉：今日待办 / 未安排 / 项目。

→ 切换成本最低，但要重写两页的布局和拖拽逻辑，窄栏适配、测试（`test/tasks-ui-layout.mjs` 等）都要重做。

## 5. 建议执行顺序

1. 先做方案 A 的第 1 条（统一日期状态），收益最大，改动集中在 `view.ts`、`tasks.ts`；
2. 再做方案 B 的计划层（`today.ts` 新增 `renderPlanLayer`，复用 `taskList.ts` 的 `openLogFor`）；
3. 最后去掉任务页的“今天”卡，调整待办到同一侧；
4. 方案 C 等 B 用一段时间后，根据实际感受再决定要不要做。

## 实施记录（2026-09-27）去冗余 1–6

- 统一入口：只保留"+ 新建"（快捷键 N），弹窗顶部三选一：已完成 / 支出 / 待做；每日页默认"已完成"，任务页默认"待做"，切换时保留已填内容。
- 去掉"关联待办"字段，关联由系统自动维护。
- 勾选任务直接写记录（按计划时段，无计划则取当前时间），并弹出"已记录 · 撤销"提示；取消勾选时删掉这条记录；"补记"也直接写记录。
- 每日页不再显示待办列表；在每日页新记的事会同时生成一个已完成任务（origin: record）。删除这条记录时任务一起删，可撤销；拖动记录时同步任务时间。
- 任务页和每日页共用选中日期、顶栏日期导航、T / ← / → 快捷键；任务页隐藏周期文字。
- 测试：tsc、core、smoke、tasks-ui-layout、chart-layout 通过；topbar-layout 仍是凌晨时段的已知问题（demo 数据当天暂无记录），与本次改动无关。
